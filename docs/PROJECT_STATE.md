## ما ينفذه P4-03B3

- البحث والاقتراحات تأتي من D1 فقط، مع تطبيع عربي/إنجليزي محافظ، aliases مخزنة في D1، وفصل المطابقة المباشرة عن «هل تقصد؟» التقريبية.
- `HarryPotter` لا يتحول إلى نتيجة مؤكدة؛ يظهر كاقتراح محافظ للعمل الصحيح، بينما `harry potter` و`هارى بوتر` يستفيدان من المطابقة المباشرة الموثوقة.
- اقتراحات البحث تعرض العربي والإنجليزي والسنة، وتدعم لوحة المفاتيح وARIA combobox/listbox.
- الرئيسية لا تحتوي CTA عام إلى `/review` بلا locator، وتعرض فقط التحليلات الأربعة الحقيقية بالحالة «تحليل تحريري جزئي — الحكم غير مكتمل».
- الواجهة تفرق بوضوح بين «تحليل تحريري جزئي للعمل» و«مراجعة موثقة لنسخة محددة».
- صفحة التحليل تعرض الخلاصة كبطاقة أساسية وDialog قابل للوصول، وتخفي القيم التقنية مثل `insufficient_data` و`decisionEligible` عن الواجهة العامة مع بقاء الحالة الداخلية دون تغيير.
- صياغات أعداد الوقائع أصبحت عربية طبيعية، والمحاور غير المحسومة مجمعة في قسم واحد بدل تكرار نفس الفقرة داخل كل محور.
- أحجام القراءة في التحليل حوالي 18px على الكمبيوتر و17px على الموبايل مع line-height مريح.
- `/titles` لم يعد يحمل 200 سجل دفعة واحدة؛ يستخدم pagination بحجم 24 وبحثًا/نوعًا/سنة وحالة مراجعة موثقة عبر استعلامات D1 server-side parameterized ومحدودة.
- `hasVerifiedReview` في `/titles` يحسب فقط من علاقة المراجعة البشرية الحقيقية: نسخة active، bundle verified ومنشورة، current approval approved، ولا يوجد بلاغ blocking مفتوح أو قيد التحقيق.
- لا توجد أي قائمة ثابتة لعناوين التحليل داخل SQL، ولا يوجد فلتر زائف «له تحليل تحريري» في `/titles`.
- صفحات الكتالوج التي لا تملك قيمة تحليلية أصلية أصبحت `noindex, follow`، بينما صفحات العناوين المرتبطة بتحليل غني وصفحات التحليل نفسها تبقى قابلة للفهرسة.
- sitemap لا يدرج صفحات الكتالوج الضعيفة؛ يدرج فقط المسارات الغنية القابلة للفهرسة.
- الرئيسية تحتوي WebSite وOrganization JSON-LD فقط، بدون SearchAction حاليًا.
- `/review` بلا locator أو مع locators مختلطة يظل fail-closed ويحمل noindex ورابطًا واضحًا للبحث.
- وصف Kids-In-Mind يظل `link_only_factual_reference`: ربط ومرجع وقائع فقط، بلا ادعاء ترخيص إعادة نشر وبلا نقل نص أو ترجمة أو درجات أو بنية المصدر.

## قاعدة الحكم لم تتغير

- كل الصفحات الأربع تظل داخليًا `decisionEligible = false` و`decisionStatus = insufficient_data`.
- ما لم يثبت يظل `uncertain`، ولا يتحول صمت المصدر إلى `none`.
- التحليل التحريري الجزئي لا يدعي مشاهدة نسخة محددة ولا يملك سلطة إصدار «مناسب/غير مناسب».
- مسار المراجعة الموثقة لنسخة محددة يحتفظ بكل بوابات النسخة/المراجعين/الاعتماد/التدقيق والبلاغات كما هو.

## Blocker مستقل بعد B3 — Editorial persistence migration

لا يوجد حاليًا جدول D1 يمثل التحليل التحريري الجزئي الحالي؛ الصفحات الأربع ما زالت registry في TypeScript. لذلك **لا يجوز** إنشاء فلتر D1 باسم «له تحليل تحريري» اعتمادًا على IDs ثابتة أو خلطه بمسار evidence publication أو المراجعة البشرية.

المهمة التالية المستقلة عند اعتمادها:

- إنشاء جداول append-only للتحليل التحريري الجزئي وفق العقد الصحيح.
- ربط المنشور بـ`title_id` و/أو `version_id` حسب قرار العقد النهائي، مع revision وpublication state وcurrent-head واضحين.
- تخزين المصادر وclaims والعلاقات اللازمة للتدقيق من دون إضعاف عقد الحقوق أو الثقة.
- نقل الصفحات الأربع الحالية من TypeScript إلى D1 **ذريًا** والتحقق من التكافؤ قبل تحويل القراءة.
- بعد ذلك فقط يمكن إضافة فلتر «له تحليل تحريري» قابل للتوسع داخل `/titles`.

**هذه migration غير منفذة في B3 ولا يجب تنفيذها ضمن checkpoint الواجهة الحالي.**

## بلاغ المستخدم — مؤجل أمنيًا

الـbackend الداخلي لدورة البلاغات موجود، لكن public intake ما زال `false`. ربط زر عام يحتاج checkpoint أمني مستقلًا يشمل server-owned binding للصفحة/الواقعة/المصدر، validation، rate limiting/anti-spam، وحماية دورة التصحيح. لذلك B3 لا يضيف زرًا وهميًا أو endpoint عامًا جزئيًا.
